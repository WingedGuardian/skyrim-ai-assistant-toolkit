# Updating the toolkit from GitHub

People find the toolkit on Nexus and download it there once. **Every later update comes from the toolkit's GitHub
releases, done by you.** The session start says, once per version, when a newer release is out. Nothing is installed
until the user says yes, and every applied update can be undone with one command.

Run every command from the toolkit folder (the game folder the toolkit was extracted into). `python` is the Python
the hooks use (`SKYGUARD_PYTHON` in `skyrim-paths.env`).

## 1. Check

```bash
python tools/agent-harness.py update-check --now
```

`update_available: true` names `installed` and `latest`. Tell the user, in one line, which version is out and ask
whether to update now. `status: unreachable` means GitHub could not be reached: say so, do not retry in a loop.
`status: off` means the user turned checking off (`.modding-agent-harness/updates.json`); honour it unless they ask.

## 2. Download and verify (changes nothing installed)

```bash
python tools/agent-harness.py update-fetch
```

It downloads the release zip into a per-user folder outside the toolkit folder (the JSON names it) and **refuses**
it unless the SHA-256
matches the digest GitHub publishes, every zip entry is safe under one folder, and the zip's `BUILD-INFO` names the
release's version and the commit its tag points at. A refusal (`ok: false`) is final: report the `error` and stop; never
work around it (no manual download, no copying over the install).

The JSON gives `source`, `candidate`, `previous` (may be null), `render_config` and `bundle`.

## 3. Stage the review (changes nothing installed)

```bash
python tools/agent-harness.py upgrade-stage --installed-root . --source "<source>" --candidate "<candidate>" \
    --previous "<previous>" --render-config "<render_config>" --destination "<bundle>"
```

Leave out `--previous` when it is null. The result counts the `collisions`: installed files whose bytes match neither
what the installed release shipped nor the new one. The list is in `<bundle>/complete.json`: the `plan.files` rows
whose `action` is `preserve_collision`, each with `installed_sha256`, `previous_sha256` and `candidate_sha256`.

## 4. Show the user, then ask

Show, in this order:
1. What the new version brings: its section of `<source>/CHANGELOG.md` (the top heading), in a few lines.
2. **Every collision, one line each, with your recommendation.** When `candidate_sha256` equals `previous_sha256`
   the new release did not change that file: recommend `keep` (nothing is lost; setup re-applies its own edits).
   For the rest, a file the user (or another session) edited is
   theirs: recommend `keep` and say what they would miss from the new version. A file setup generates
   (the agent instruction files, the hook definitions, hook scripts with filled-in paths) is regenerated by setup
   after the update: recommend `candidate`. A project settings file: recommend `merged_settings` (their own settings
   kept, the new hooks taken).
3. That nothing is replaced until they say yes, and that the update can be undone.

Never decide a collision silently, and never pick `candidate` for a file the user edited without their explicit yes
for that file. Their notes (`KNOWLEDGEBASE.local.md`, `CLAUDE.local.md`) and local settings are always kept.

## 5. Apply (only after the user's yes)

Write their choices to `<bundle>/../choices.json` as `{"path": "keep" | "candidate" | "merged_settings", ...}`: one
entry per collision, plus one for every key of `merged_settings_hashes` in `complete.json` (the project hook
settings; the upgrader requires the choice explicitly): `"merged_settings"` (their own settings kept, the new hooks
merged in), except `"keep"` for a settings file that still holds setup's unfilled double-brace placeholders, which belongs to an agent
this install never set up (setup renders it if that agent is set up later). Everything else follows the review. Ask them to close any other agent session or editor working in
this folder, then:

```bash
python tools/agent-harness.py upgrade-apply --installed-root . --bundle "<bundle>" \
    --review-sha256 "$(python -c "import hashlib,sys;print(hashlib.sha256(open(sys.argv[1],'rb').read()).hexdigest())" "<bundle>/complete.json")" \
    --choices "<bundle>/../choices.json" --quiescent
```

Record the operation ID it prints. If it refuses because of custom pre-tool hook handlers, stop and point the user to
`docs/upgrading-native-hooks.md`; do not force it.

## 6. Finish

```bash
bash setup.sh --agent auto
bash tools/hook-canary.sh
```

Then tell the user:
- the version now installed, and the operation ID;
- how to undo it: `python tools/agent-harness.py upgrade-rollback <operation ID> --installed-root . --quiescent`;
- to **restart the agent session** (hooks and instructions load at session start), and on Codex to approve the
  changed hooks in its hook review;
- if `Data/SKSE/Plugins/ToolkitProbe.dll` exists: the release also carries a `ToolkitProbe.zip` to install through
  their mod manager (never copy it into `Data` yourself).

If setup or the canary fails, say so with the output, and offer the rollback.
